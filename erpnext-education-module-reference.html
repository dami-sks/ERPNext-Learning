ERPNext v16 · Education Module

The complete field guide to Frappe Education

This document teaches every doctype and tool in the Education module in plain language, in the order you actually need to build them. It combines the official Frappe documentation with what really happened during a live ACE curriculum school implementation for Arise Education Network (AEN) in Uganda, on ERPNext v16. Where the documentation and the real system disagreed, both sides are shown.

Source 1: docs.frappe.io/education, all linked pages Source 2: Arise Education Network live implementation, site ariseedn.local, v16
Build order

Layer 01

General education

The calendar backbone and the global defaults. Everything else in the module points back to these three records, directly or indirectly.

Academic Year

General

An Academic Year is the top-level time container for a school year, for example 2025-2026. It holds a start date and an end date, and every other academic record in the system, enrollments, assessments, attendance, fees, points back to one.

Why it exists

Every doctype that changes year to year needs a stable reference point so records do not blur together across years. Reports, fee collections, and grading all filter by Academic Year first.

Dependencies

  • None. This is the first thing you create.

How to create it

  1. Go to Education > Academic Year > New.
  2. Enter the year name, for example 2025-2026.
  3. Set the start date and end date.
  4. Save.

If this is missing

Nothing downstream can be created. Student Group, Program Enrollment, Assessment Plan, Fee Structure, and Fee Schedule all have an Academic Year field, and several treat it as a hard filter for reporting and defaults.

Faster path

If you set the current Academic Year inside Education Settings once it exists, it becomes the default value pre-filled on every form that has this field, saving a click on every single record you create afterward.

Academic Term

General

An Academic Term is a slice inside an Academic Year, a quarter, trimester, or semester. Most Ugandan and East African schools run three terms per year, and AEN follows that pattern with Term 1, Term 2, and Term 3 inside 2025-2026.

Why it exists

Fee Schedules, Program Enrollments, Student Groups, and Assessment Plans are all filtered by term, not just by year. A school that bills termly, not annually, needs this layer to exist.

Dependencies

  • Academic Year

How to create it

  1. Go to Education > Settings > Academic Term.
  2. Select the parent Academic Year.
  3. Enter start and end dates for the term.
  4. Save.

Docs versus reality

This is the single most expensive mismatch to get wrong. At AEN, Student Groups and Program Enrollments were built against 2025-2026 (Term 2 2026), but Fee Structures were built against 2025-2026 (Term 3 2026). The result was Fee Schedules that consistently showed zero students, with no error message explaining why. Every doctype that references Academic Term must reference the exact same term string, character for character, or the join between Student Group and Program Enrollment silently returns nothing. Decide your term naming and stick to it before you build anything downstream.

Common errors

  • Fee Schedule shows zero Total Students, even though the Student Group clearly has students in it. Almost always a term mismatch between the group and the enrollment, not a bug.
  • Assessment Plan for the wrong term cannot simply be edited once submitted. It has to be cancelled and recreated with the correct term.

Education Settings

General

A single settings document that controls defaults and behavior across the entire module: the current Academic Year and Term, how Instructor records are named, whether a User account is created automatically for every new Student, and whether Sales Invoices are created as Draft or Submitted.

How to configure it

  1. Go to Education > Settings > Education Settings.
  2. Set the current Academic Year and Academic Term. These become the pre-filled default everywhere that field appears.
  3. Set an Attendance Freeze Date if you want to lock attendance editing after a cut-off.
  4. Choose how Instructor records are named: Full Name, Naming Series, or Employee Number.

Fields worth knowing

  • Skip User Creation for New Student: leave this off if students need portal login access. Turning it on blocks the User record needed for the Student Portal.
  • Submit Sales Invoice from Program Enrollment / Fee Schedule: off means every generated invoice sits in Draft until someone submits it by hand.
  • Make Academic Term Mandatory: forces the Program Enrollment Tool to require a term, which prevents the exact term-mismatch failure described above.

Portal Settings tab

School abbreviation, logo, and Razorpay credentials for online fee collection live here. This tab only matters if the Student Portal is switched on for parents and students.

Practical advice

Visit this document before creating a single Academic Year or Fee Structure. Turning on Make Academic Term Mandatory early would have prevented the entire AEN Term 2 versus Term 3 problem, since the Program Enrollment Tool would have refused to let a term go unset.

Layer 02 to 03

People & admissions

The human records. Everything billing-related, academic-related, and attendance-related eventually connects back to a Student, and every Student connects to a Guardian.

Guardian

People

A Guardian is the record for a student's parent or responsible adult: father, mother, or another relative. One Guardian can be linked to several students, which matters for schools with siblings enrolled.

How to create it

  1. Go to Education > Student > Guardian > New.
  2. Enter the Guardian's name, and optionally email, mobile number, occupation, and work address.
  3. Save. It can also be created inline from within a Student form.

Features worth knowing

  • Guardian Of auto-populates once a Student links to this Guardian.
  • Invite as User sends a portal login invitation by email, for parents who need to see fees and grades.

Docs versus reality

The documentation shows creating a Guardian by name through the UI. At AEN scale, bulk Guardian import required an EDU-GRD-2026-XXXXX style ID in the import file, not the Guardian's name. The importer resolves Guardians by ID, and a plain name in that column fails silently or creates a duplicate. Export an existing Guardian first to see the exact ID format your site uses before building an import sheet.

Student

People

The Student record holds a student's personal information: name, date of birth, gender, address, guardian links, and sibling details. It is the hub every other academic and financial record connects back to.

Dependencies

  • User (only if portal access is needed immediately)
  • Guardian (can be created inline from this form)

If this is missing

Nothing billing-related, attendance-related, or assessment-related can exist. Program Enrollment, Student Group, Fee Schedule, and Assessment Result all require a Student to already exist.

How to create it

  1. Go to Education > Student > Student > New.
  2. Enter First, Middle, and Last Name.
  3. Add Student Email Address and Joining Date.
  4. Optionally fill Personal Details, Home Address, Guardian Details, and Sibling Details.
  5. Save.

Common errors

  • Bulk import requires EDU-STU-2026-XXXXX style IDs for linked fields such as Guardian, not names typed as plain text.
  • Forgetting to uncheck the Enabled box after recording a student's Exit Details leaves a departed student active in every group and report.
Once saved, a full dashboard becomes visible on the Student form showing linked Program Enrollments, Fee Schedules, Attendance, and Assessment Results for that student in one place.

Student Applicant

People

A record created when a prospective student applies for admission, either manually or through the public Student Applicant web form. Its status moves from Applied through Approved or Rejected, and clicking Enroll converts an approved applicant directly into a Student plus a Program Enrollment in one action.

Dependencies

  • Academic Year
  • Academic Term
  • Program

How to create it

  1. Go to Student Applicant > New.
  2. Enter First Name, Program applied for, and Student Email.
  3. Save.

Docs versus reality

ERPNext ships a simple two-state status field: Applied and Enrolled or Rejected. For AEN, this status field was extended to reflect a real admission pipeline: Application Received, Diagnostic Scheduled, Diagnostic Completed, Offer Pending, and Offer Accepted, since ACE schools run a diagnostic placement test before offering a grade level. This is a configuration change, not a code change, done through the status field's options.

Student Admission

People

A document that publishes a public online admission portal on the ERPNext-generated website for one Program, with its own route, eligibility rules, and application window. This is the doctype that makes the Student Applicant web form appear online for a given intake.

Dependencies

  • Academic Year
  • Program

How to create it

  1. Go to Student Admission > New.
  2. Select Academic Year and enter a Route, the URL path for the portal.
  3. Set Admission Start and End Date.
  4. Check Publish on Website when ready to go live.

Additional fields

Minimum and Maximum Age, Application Fee, and a Naming Series for how applicant records get numbered all live here, alongside an Introduction field shown to applicants before they apply.

Student Category

People

A simple classification tag for students, used for fee concessions or reporting groups: scholarship recipients, students with disabilities, foreign nationals, or any other category a school needs to treat differently at fee time.

Dependencies

  • None. This is a Level 02 independent master.

Where it is used

Selected on Program Enrollment for a given student, and selected on Fee Structure to filter which students a particular fee schedule applies to. A scholarship Fee Structure at zero cost, filtered by Student Category, is the standard way to handle scholarship students without manual discounting on every invoice.

How to create it

  1. Go to Education > Settings > Student Category > New.
  2. Enter a name.
  3. Save.

Student Batch

People

A batch is a named cohort of students within a Program, selected at Program Enrollment time. A Student Group can later be built from an entire batch rather than course by course.

How to create it

  1. Go to Education > Settings > Student Batch Name > New.
  2. Enter a batch name.
  3. Save.

Where it is used

Selected on Program Enrollment. A Student Batch-Wise Attendance report can then show how many students from a given batch were present on any date.

Layer 04

Program & course

The academic structure. A Program is the curriculum a student enrolls into, built from one or more Courses, and taught by Instructors.

Course

Program

A Course is a subject: Mathematics, English, Bible Studies. Each Course carries its own default Grading Scale and Assessment Criteria, so every assessment built against that Course inherits a consistent grading structure.

Dependencies

  • Department
  • Topics (optional, see below)

How to create it

  1. Go to Education > Masters > Course > New.
  2. Enter Course Name and Department.
  3. Add Topics if the curriculum is digital.
  4. In the Assessment tab, set a Default Grading Scale and add Assessment Criteria rows.
  5. Save.

Docs versus reality

The documentation treats Topics as a normal step, a set of digital content units a Course covers. For AEN, Topics were left entirely blank. Topics exist for digital learning content delivered through the Frappe LMS module, videos and online modules a student watches. ACE curriculum students work through physical PACE booklets, so there is no digital content to attach. Leaving Topics empty caused no negative effect anywhere else in the system. If your school teaches from physical material, do not feel obligated to fill this field.

The AEN assessment criteria pattern

13 Courses were built, and all 13 reused the same 12 Assessment Criteria named PACE Slot 1 through PACE Slot 12, each weighted 8.33, with slot 12 weighted 8.37 so the total lands at exactly 100. Since the same generic Course record, Mathematics, is reused from Grade 1 through Grade 8, the specific PACE number for each slot is captured later, at Assessment Plan and Assessment Result level, not on the Course itself.

Program

Program

A Program is the curriculum a school offers at a level: an Economics Major, or ACE Grade 5. It is built from a collection of Courses and is the thing a student formally enrolls into.

Dependencies

  • Department
  • Course (at least one)

How to create it

  1. Go to Education > Masters > Program > New.
  2. Enter Program Name and Abbreviation.
  3. Select Department.
  4. Add the Courses that belong to this Program.
  5. Save.

Portal settings

A Program can be published on the website with Is Published, allowing Allow Self Enroll for applicants to enroll themselves, an Intro Video, and a Description shown publicly.

Docs versus reality

There is no rule that Programs must be named a particular way. At AEN, Programs were deliberately named ACE Grade 1 through ACE Grade 12 rather than the more curriculum-accurate ACE Level, because that is the language staff, parents, and the school's own signage actually use. Match the Program name to how the people running the school talk about it, not to the vendor's internal terminology, since the name appears on every invoice and report a parent will see.

Instructor

Program

A teacher, tutor, or professor record, linked to an existing Employee. It maintains an Instructor Log, a running history of every Course and Student Group a teacher has been assigned to.

Dependencies

  • Employee (must exist first)
  • Department

How to create it

  1. Go to Education > Masters > Instructor > New.
  2. Select the Employee.
  3. Select the Department.
  4. Save.

After creation

Student Group, Course Schedule, and Assessment Plan can all be created directly from an Instructor's record. On an Assessment Plan specifically, an Instructor can be assigned as either the Supervisor or the Examiner.

Layer 05

Enrollment

This is where a Student stops being a name in the system and becomes a billable, gradable, attendance-tracked participant in a Program. It is also the layer where the entire AEN Fee Schedule failure originated, so read this section closely.

Program Enrollment

Enrollment

The record of one student enrolling into one Program for one Academic Term. It is the join that everything downstream, Student Group, Fee Schedule, Assessment Plan, quietly relies on, even though none of those forms mention Program Enrollment directly.

Dependencies

  • Student
  • Program
  • Academic Year, Academic Term
  • Fee Structure (for the Fees subtable)

How to create it

  1. Go to Program Enrollment > New.
  2. Select Student and Program.
  3. Select Academic Year and Academic Term.
  4. Save, then Submit.

Docs versus reality, the core lesson of this whole document

The documentation describes Program Enrollment as a straightforward enrollment record. What it does not make obvious is that Fee Schedule does not simply count students inside a Student Group. Internally it runs a join between Student Group Student and Program Enrollment, filtered on a matching Academic Term and on docstatus = 1, meaning submitted, not just saved. A Student Group with nine visible students and zero matching Term 3 Program Enrollments will show a Fee Schedule with zero students, with no error explaining why. This single mismatch, enrollments sitting in Term 2 while Fee Structures were built for Term 3, was the root cause behind a multi-session debugging effort at AEN. Confirm your Program Enrollments are both term-matched and submitted before troubleshooting anything else in the fee chain.

Common errors

  • CSV import of Program Enrollments at scale fails or behaves unreliably because of child table handling (the Fees and Courses subtables). Bulk import through the standard Data Import tool is not reliable for this doctype past a handful of records.
  • A saved but unsubmitted Program Enrollment is invisible to the Fee Schedule join, since it filters on docstatus = 1.

Faster, more reliable path

At AEN, bulk Program Enrollment creation was done through the bench console, not CSV import, once the CSV importer proved unreliable for the volume involved (50 records across Grades 3 to 10). A minimal console pattern looks like this:

import frappe
pe = frappe.get_doc({
    "doctype": "Program Enrollment",
    "student": "EDU-STU-2026-00011",
    "program": "ACE Grade 5",
    "academic_year": "2025-2026",
    "academic_term": "2025-2026 (Term 3 2026)",
    "enrollment_date": "2026-09-08"
})
pe.insert()
pe.submit()
frappe.db.commit()

Run this per student, or loop it over a list of student IDs. Remember to submit(), not just insert(), or the record will be invisible to Fee Schedule regardless of how correct the term is.

Program Enrollment Tool

Enrollment

The intended UI path for bulk-enrolling students, either brand new students pulled from Student Applicant, or existing students being promoted into a new term or Program from their prior Program Enrollment.

How to use it

  1. Go to Education > Tools > Program Enrollment Tool.
  2. Set Get Students From to either Student Applicant or Program Enrollment.
  3. Enter the target Academic Year, Academic Term, and Program.
  4. Click Get Students, review the fetched list, remove any that should not be included.
  5. Click Enroll Students to create Program Enrollments in bulk.

Docs versus reality

This is the documented, correct path for exactly the kind of term promotion AEN needed, moving existing Term 2 students into Term 3. In practice it was bypassed in favor of the bench console, because the console gave precise, auditable control over which student IDs went into which term, at a point in the debugging process where trust in the automated tooling had already broken down. If you are promoting students in bulk and have not yet hit a term-mismatch problem, start with this tool rather than the console. Turning on Make Academic Term Mandatory in Education Settings first will stop this tool from ever creating a term-less enrollment.

Student Group

Enrollment

A Student Group is a class section: a specific cluster of students taking the same course or belonging to the same batch, for a specific Academic Term. This is what a Fee Schedule, Course Schedule, and Assessment Plan all actually attach to.

Dependencies

  • Student
  • Program Enrollment, submitted, correct term
  • Student Batch Name, Student Category (optional filters)
  • Instructor

Group Based On options

  • Batch: pulls every student in a batch.
  • Course: pulls every student enrolled in that specific course.
  • Activity: free selection, no automatic criteria, used for clubs or events.

How to create it

  1. Go to Student Group > New.
  2. Select Group Based On.
  3. Enter Student Group Name, Academic Year, Academic Term, Program.
  4. Click Get Students, which pulls matching students automatically.
  5. Save.

Docs versus reality

Get Students is described as a reliable one-click fetch. It only works when a student's Program Enrollment academic_term string exactly matches the Student Group's academic_term string. When AEN's enrollments sat in Term 2 while groups were being built for Term 3, Get Students silently returned nothing, with the form giving no indication of why. The fix at AEN was populating Student Groups directly through the bench console once the correct Term 3 Program Enrollments existed, rather than repeatedly retrying Get Students in the browser.

AEN's confirmed naming convention for Student Group: Course/Program/Academic Year (Term), for example Mathematics/ACE Grade 5/2025-2026 (Term 3 2026). Keeping this format consistent made troubleshooting the term-mismatch issue far easier, since the term was visible directly in the group name.

Student Group Creation Tool

Enrollment

Bulk-creates Student Groups across every Course in a Program in one action, instead of building each group one at a time.

How to use it

  1. Go to Education > Tools > Student Group Creation Tool.
  2. Select Academic Term and Program.
  3. Optionally check Separate course based Group for every Batch, to split each course by batch.
  4. Click Get Courses, review or edit the fetched course list.
  5. Click Create Student Groups.

Docs versus reality

Like Get Students on the Student Group form itself, this tool does not auto-populate students into the groups it creates when Program Enrollments and the target Academic Term do not match. At AEN, this meant the tool successfully created the group shells for Term 3 but left them empty of students, requiring the same console-based population workaround described under Student Group above.

Layer 06

Scheduling

The timetable layer. None of this is mandatory for a working fee and assessment system, but it is what turns a Student Group into an actual daily routine.

Course Schedule (what most people call the Timetable)

Schedule

A single scheduled slot: one Student Group, taught by one Instructor, for one Course, in one Room, at a specific time. A full timetable is simply many Course Schedule records viewed together on a calendar. This is also the doctype attendance is marked against, for schools that track attendance per lecture rather than per day.

Dependencies

  • Student Group
  • Instructor
  • Course
  • Program
  • Room

How to create it

  1. Create from the Schedule Calendar view.
  2. Select Student Group, Instructor, Course.
  3. Set From Time and To Time.
  4. Select Room.

Marking attendance from here

Clicking Attendance on a Course Schedule opens a checklist of every student in that group, with checkboxes for Present or Absent, plus Check All and Uncheck All shortcuts for fast marking.

Topic

Schedule

A sub-unit of digital content within a Course, intended for schools delivering material through the Frappe LMS module: video lessons, readings, or online modules a student works through.

When to skip it

If a school teaches from physical material rather than digital content, as with ACE curriculum PACE booklets, this field can be left empty entirely with no negative effect elsewhere. Do not feel obligated to populate Topics just because the Course creation flow prompts for it.

Course Scheduling Tool

Schedule

A bulk version of Course Schedule, used to generate a recurring timetable slot, for example every Monday and Wednesday at 9am, across a date range, instead of creating each individual Course Schedule record by hand.

Dependencies

  • Student Group
  • Instructor
  • Course
  • Room
Not used at AEN, since ACE curriculum students self-pace through PACE booklets rather than attending fixed lecture slots. This tool matters most for schools running a conventional lecture timetable.

Room

Schedule

A physical space record: a classroom, examination hall, or lab, with a room number and seating capacity. This is what Course Schedule and Assessment Plan attach a venue to.

How to create it

  1. Go to Education > Masters > Room > New.
  2. Enter the room name, room number, and seating capacity.
  3. Save.
Layer 02 & 06

Assessment

The official documentation gives an exact setup order for this module, and it is worth quoting directly: build Assessment Criteria first, then Assessment Group, then Grading Scale. Only after a Student Group and Course exist can an Assessment Plan be scheduled. Assessment Results follow from there, ideally entered in bulk through the Assessment Result Tool rather than one at a time.

Assessment Criteria

Assessment

A single parameter a student is graded on within a course: Writing, Practicals, Presentation, or in AEN's case, PACE Slot 1 through PACE Slot 12. Marks entered against an Assessment Result are broken down by these criteria, not given as one lump score.

Dependencies

  • None. Build this first, it is a Level 02 independent master.

Where it attaches

Added to a Course's Assessment tab with a Weightage, and later pulled automatically into any Assessment Plan built for that Course.

The AEN pattern

12 generic criteria named PACE Slot 1 through PACE Slot 12 were created once, then reused across all 13 Courses at every grade level, each weighted 8.33 except slot 12 at 8.37, for an exact total of 100. Because the same Course record spans multiple grades, the specific PACE number for each slot is recorded later, at Assessment Plan and Assessment Result level, not baked into the criteria name itself.

Assessment Group

Assessment

A tree-structured master that defines the hierarchy of examinations at a school, for example one Assessment Group per Academic Term within an Academic Year, or categories like Term Tests and End of Term Exams.

Dependencies

  • None. Build alongside Assessment Criteria.

Where it is used

Selected on every Assessment Plan, to categorize which examination cycle that plan belongs to.

A naming trap worth flagging

Assessment Group is easy to confuse with Assessment Criteria Group, a separate, smaller field that lives inside the Course's Assessment tab and simply labels a cluster of Assessment Criteria for organizational purposes, for example naming all 12 PACE Slot criteria under one label called PACE Completion. Assessment Group is the term-level examination hierarchy used on Assessment Plan. Assessment Criteria Group is a cosmetic grouping label on the Course form. They sound identical and control entirely different things.

Grading Scale

Assessment

Defines the score thresholds that translate a percentage into a letter grade or achievement level, for example 90 percent and above is an A+, 80 and above is an A-.

Dependencies

  • None. Build alongside Assessment Criteria and Assessment Group.

Where it is used

Set as the Default Grading Scale on a Course, and automatically pulled into any Assessment Plan built for that Course.

At AEN, only one Grading Scale, named ACE Standard, was ever submitted in the system. Because Frappe auto-selects the only submitted Grading Scale as the default wherever this field appears, every Course inherited ACE Standard automatically without it being explicitly set on each one.

Assessment Plan

Assessment

A scheduled examination event for one Student Group and one Course: when it happens, in which room, supervised and examined by which Instructors, and against which Grading Scale and Assessment Criteria.

Dependencies

  • Student Group
  • Course
  • Program
  • Assessment Group
  • Grading Scale

How to create it

  1. Go to Assessment Plan > New.
  2. Select Student Group, Course, Assessment Group.
  3. Grading Scale auto-fills from the Course.
  4. Set Schedule Date, From Time, To Time, Room, Examiner, Supervisor.
  5. Enter Maximum Assessment Score; Assessment Criteria auto-populate from the Course.
  6. Save.

Common errors

  • From Time and To Time are mandatory fields. Bulk CSV import of Assessment Plans fails when these are left blank or formatted inconsistently, along with general child table grouping issues in the Assessment Criteria subtable.
  • A submitted Assessment Plan built for the wrong Academic Term cannot be edited in place. It has to be cancelled and recreated with the correct term, exactly as with Program Enrollment.

Faster path for bulk creation

At AEN, 28 Assessment Plans across two grades were built through a Python script rather than the UI form, generating each plan's dictionary of field values programmatically and inserting through frappe.get_doc().insert(), which handled the child table population far more reliably than CSV import did.

Assessment Result

Assessment

A log of the marks or grade one student earned on one Assessment Plan, broken down by Assessment Criteria. This record is created in the background, not usually by hand.

How it gets created

Almost always generated automatically by the Assessment Result Tool as marks are entered, rather than created directly.

Assessment Result Tool (the "Assessment Tool")

Assessment

The bulk marks-entry screen. Select an Assessment Plan, and every student in that Student Group is fetched into a table with one column per Assessment Criteria, ready for scores to be typed in directly.

How to use it

  1. Go to Education > Tools > Assessment Result Tool.
  2. Select the Assessment Plan.
  3. Enter marks for each student, per criteria column.
  4. Move to the next student. An Assessment Result record is auto-created in the background for each one as you go.
At AEN, this workflow produced 35 submitted Assessment Results, giving a complete end-to-end PACE tracking demo from enrollment through to graded results.

Final Assessment Grades

Assessment

A report, not a doctype to create records in, that shows the overall final grade for each student at the end of a term or program, rolling up individual Assessment Results into a single summary grade per student per Grading Scale.

Where to find it

Education > Reports > Final Assessment Grades. Useful for report card generation and for spotting which students have gaps in their assessment record before a term closes.

Layer 07 to 08

Fees management

The billing chain. This is the layer with the most silent failure modes in the entire module, because three separate doctypes each auto-populate fields from the one before it, and any break in that chain shows up as a zero, not an error.

Fee Category

Fees

A component of fee calculation: Tuition Fees, Hostel Fees, Transport Fees. Fee Categories are the line items a Fee Structure is built from.

Dependencies

  • None. Build this first, it is a Level 02 independent master.

How to create it

  1. Go to Education > Fees > Fee Category > New.
  2. Enter Name and Description.
  3. Save.

What actually happens behind the scenes

From v15.1 onward, creating a Fee Category silently creates a matching Item record in the Item doctype. From v15.4, a child table called Accounting Defaults appears, letting a Fee Category route income to a different Company, Income Account, or Cost Center than the default set on Fee Structure. This matters directly for multi-entity setups: AEN's holding company, Arise Education Network, was deliberately kept out of every Fee Category accounting default and every Fee Schedule Company field, since the holding company never bills students directly, only the two operating schools underneath it do. Get this separation right at the Fee Category level and it holds correctly all the way through to the Sales Invoice.

Fee Structure

Fees

A reusable template of fee components and amounts for a Program, used to generate Fee Schedules or individual Fees records. Think of it as the price list before it becomes an actual bill.

Dependencies

  • Academic Term, Academic Year
  • Program
  • Student Category (optional filter)

How to create it

  1. Go to Fee Structure > New.
  2. Select Program and other basic details.
  3. In the Components table, add Fee Category rows with amounts.
  4. Set Receivable Account, Income Account, and Company.
  5. Save and Submit.

What Company controls here

Whichever Company is selected on Fee Structure is the Company every generated Sales Invoice will be created against. In a group-of-companies setup, this is the field that decides which legal entity actually bills the student, not the Program and not the holding company above it.

From v15.1 onward, multiple Fee Schedules can be generated directly from one submitted Fee Structure using the Create Fee Schedule button, which opens a modal to pick a fee plan, adjust amounts, and select a Student Group, rather than building each Fee Schedule from scratch.

Fee Schedule

Fees

Turns a Fee Structure into an actual billing timeline for a specific Student Group: a due date, a fee breakdown, and, once submitted, a Create Sales Invoice button that generates one invoice per student in the group.

Dependencies

  • Fee Structure, submitted
  • Student Group, populated with students
  • Underlying Program Enrollments, submitted, correct term

How to create it

  1. Go to Fee Schedule > New.
  2. Select Fee Structure; Fee Break Up for Each Student auto-populates.
  3. Select Academic Year, Academic Term, Due Date, Student Group.
  4. Save and Submit.
  5. Status changes from Draft to Invoice Pending. Click Create Sales Invoice.

Common errors, in the order AEN actually hit them

  • Total Students shows zero. Almost never a Student Group problem. Check first whether the students in that group have submitted Program Enrollments for the exact matching Academic Term. If Term 3 has no Program Enrollments, Fee Schedule sees zero students, regardless of how many students are visibly sitting inside the Student Group table.
  • All invoice amounts show as 0. The Components child table did not auto-populate from the Fee Structure, usually after a CSV import route rather than the native UI flow. Open the Fee Schedule and manually add components from the Fee Structure, or rebuild through the console with components explicitly appended.
  • Total Students still blank after saving, even with a confirmed non-zero join count. A known v16 UI rendering issue: the browser's fetch that writes total_students runs once, at the moment a Student Group is selected, and does not always refresh afterward. Removing and re-adding the Student Group row sometimes forces a refresh; if not, this is a case for creating the Fee Schedule through the console instead.

When the console becomes the correct path, not just a workaround

At AEN, once students were added to Student Groups directly through the console rather than through the native Get Students flow, the Fee Schedule UI's student-count fetch stopped recognizing those students correctly, even though the underlying data was accurate. The fix was creating Fee Schedules through the console too: querying the actual join directly, setting total_students explicitly, and building each fee component row by hand. One detail is easy to miss: when a fee component's total field is set in the browser, JavaScript computes it before the form is even submitted. Going through the console bypasses that JavaScript entirely, so total arrives as None and the Python validator crashes trying to sum it. The fix is setting total explicitly on every component row inside the console script, replicating what the browser would have done automatically. Once a site's data has been built this way for even one Fee Schedule, treat the console as the permanent, correct path for that site going forward, not an occasional workaround.

Fees (covers "Student Fee" and "Fee Receipt")

Fees

The individual fee record for one student: what they owe, the due date, and once paid, the payment record against it. There is no separate doctype called Student Fee or Fee Receipt in the Education module; both are informal names for what this Fees doctype, and the Sales Invoice it generates, actually do.

Dependencies

  • Student
  • Fee Category
  • Fee Structure

How to create it

  1. Go to Fees > New.
  2. Select Student, add Due Date.
  3. Select a Fee Structure; components auto-populate.
  4. Save.

Where the receipt actually comes from

What most people mean by a Fee Receipt is the printed or PDF version of a submitted Fees record or its Sales Invoice, generated from the Letter Head and Print Heading set under Printing Settings on the Fees or Fee Schedule form, not a separate record type.

The v15.1 onward flow

Since v15.1, a Sales Invoice is created against a student and a Fee Schedule, with every Fee Category listed as a line item on the Sales Invoice Item table. Since v15.3, a Sales Order can be created instead of a Sales Invoice, useful for schools that want to show a pending charge before the student has actually joined, converting to an invoice only once they enroll.

Payment can be recorded directly from a Fees record by selecting a Mode of Payment in the Payment Entry and submitting.

Student Attendance

Attendance

A single attendance record for one student, on one date, against either a Course Schedule or a Student Group.

How to create it

  1. Select Student, Course Schedule or Student Group, and date.
  2. Set Status.
  3. Save.

v15.3.1 onward

Three states are available: Present, Leave, and Absent. The status can be changed even after the document is submitted, which was not possible in earlier versions.

For bulk marking rather than one student at a time, use the Student Attendance Tool below.

Student Attendance Tool

Attendance

Bulk attendance marking for an entire Student Group at once, filterable by Batch, Course, or Activity, rather than opening one Student Attendance record per student.

How to use it

  1. Go to Education > Attendance > Student Attendance Tool.
  2. Select the Student Group basis and date.
  3. Student details auto-fetch.
  4. Mark attendance for the fetched list and save.

Student Leave Application

Attendance

A formal leave record for a student across a date range, functioning as the official system record when a parent submits a leave request.

How to create it

  1. Select Student, From Date, To Date.
  2. Choose Attendance Based On: Course Schedule for per-lecture tracking, or Student Group for whole-day tracking.
  3. Optionally check Mark as Present, if the student is representing the school at an event.
  4. Save.

What happens on submission

A Student Attendance record is created automatically, set to Leave, or to Present if Mark as Present was checked. If any date within the leave period falls on a holiday, that date is skipped. Total Leave Days is calculated automatically, excluding holidays from the default Holiday List.

Cancelling a Student Leave Application automatically cancels the linked Student Attendance record it created.

Student Log

Other

A standalone, chronological note attached to a Student, used for behavioral observations, achievements, or any incident worth recording outside of formal Assessment Results. It carries its own Academic Year field, so notes can be filtered by the year they were made.

Where it is useful

Building a running record of a student's conduct or milestones over time, visible from the Student dashboard alongside their academic and financial history.

Student Portal

Other

A self-service website, bundled with the Education module from v15.2.0 onward, where students and parents can log in to check their timetable, attendance, pay fees online, and view current and previous grades, without needing desk access to ERPNext itself.

Dependencies

  • User account on the Student record (Skip User Creation for New Student must be off in Education Settings)
  • Razorpay credentials, if online payment is required

Where to configure it

Education Settings, Portal Settings tab: attendance-based-on-course-schedule behavior, payment gateway keys, and the school's abbreviation and logo shown on the portal.

Tracking the Progress

Other

Not a doctype on its own, but the documentation's guidance page on reading a student's overall academic picture from the records this module already generates. The most direct route is the dashboard visible on any saved Student record, which surfaces linked Program Enrollments, Fee Schedules, Attendance, and Assessment Results in one place, without needing to open each doctype's list view separately.

Practical use

For a single student, start from their Student record dashboard. For a whole cohort, use the Final Assessment Grades and Assessment Plan Status reports, alongside Student Fee Collection for the financial side, rather than trying to piece the picture together from individual records.
